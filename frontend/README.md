# pharma-agent-web

The web frontend of the pharma AI agent: a React Router application with server rendering for the public pages and client-only chat and settings pages behind sign-in.

## Structure

- `app/routes/`: route modules. They stay thin and compose features.
- `app/features/<feature>/`: one folder per feature, with `components/` (React components), `hooks/` and `lib/` (logic without UI). Tests sit next to the code they test.
- `app/api/`, `app/components/`, `app/hooks/`, `app/i18n/`, `app/lib/`: shared code. `app/api/gen/` is generated by orval from the backend OpenAPI document.

Dependency rules:

- Shared code never imports features or routes, and features never import routes.
- A feature imports another feature only in these one-way directions: `chat` → `conversations`, `shell` → `auth`, `conversations`, and `organizations` → `audit`. Everything else is composed in routes.
- No import cycles.

`npm run lint` enforces the rules with `import/no-cycle` and `no-restricted-imports` overrides in `.oxlintrc.json`. `app/architecture.test.ts` resolves every import, relative ones included, and checks the same rules plus the folder layout. It also checks that the lint overrides match its table of allowed directions, so a new direction is added to both.

## UI components

Every widget comes from shadcn (style `base-nova`, on Base UI), added with `npx shadcn@latest add <name>` into `app/components/ui/`. Before building anything by hand, check the registry with `npx shadcn@latest view <name>`. The chat screen uses shadcn's own `message`, `bubble`, `marker` and `message-scroller`. Multi-value fields and multi-selects use `combobox` with chips, toolbars use `toggle`, and rendered Markdown uses the Tailwind typography plugin (`prose`). Data comes from the TanStack Query hooks that orval generates, and forms use react-hook-form with zod and shadcn `field`. The few shared compositions on top of shadcn live in `app/components/` (`tags-input`, `name-form`, `code-step`).

A few files in `app/components/ui/` differ from the registry on purpose because `npm run lint` (jsx-a11y) forbids the registry's version. `role="group"`/`role="list"` are dropped from `input-group`, `field`, `item` and `button-group`, and the addon click-to-focus handler is dropped from `input-group`. `spinner` is `aria-hidden` (callers wrap it in `<output>`), and `toggle-group` builds its gap style without a type assertion. When `shadcn add` offers to overwrite these files, keep the local version.

## End-to-end tests

The Playwright suite in `tests/e2e/` runs the production build of this app against the backend E2E server: real FastAPI, Postgres and Qdrant, with a fake LLM and a fixture corpus. It covers:

- registration, login and logout
- session expiry
- asking a question and seeing the phase, the `[1]` citation, its preview and the full text
- 👎 feedback with a note
- loading older messages
- changing language and theme
- the `/en/` hreflang links

### Prerequisites

1. From the repository root: `docker compose up -d postgres qdrant`.
2. Backend dependencies: `uv sync --directory ..` (the uv workspace at the repository root). The E2E server's settings are described in the "Server E2E" section of `backend/README.md`. On every start it recreates the `pharma_e2e` database (override with `E2E_POSTGRES_DSN`) and the Qdrant alias `e2e_chunks_current` (Qdrant URL from `E2E_QDRANT_URL`); your dev data is not touched.
3. Chromium for Playwright: `npx playwright install chromium` (already done if you followed the setup above).

### Run

```bash
npm run e2e                                   # starts every server, runs all specs
npx playwright test --headed --debug          # step through in a browser
npx playwright show-report                    # HTML report of the last run
```

### How the servers are wired

| Server             | Command                                                       | Port             |
| ------------------ | ------------------------------------------------------------- | ---------------- |
| Backend E2E server | `uv run python -m tests.e2e.server --port 8001` in `backend/` | 8001             |
| Frontend           | `npm run build && npm start`                                  | 3100             |
| One-origin proxy   | `node tests/e2e/proxy.ts`                                     | 3200 (`baseURL`) |

In production nginx gives the browser one origin (`/api/*` to FastAPI, everything else to React Router). `tests/e2e/proxy.ts` does the same with http-proxy-3, so cookies, CSRF and streaming behave as deployed and no test-only code enters the app. Locally, servers already running on these ports are reused; with `CI` set, Playwright always starts fresh ones.
